# PI4-241 — Configurar o banco de dados PostgreSQL

## O que esta historia entrega

- Ambiente PostgreSQL 17 local isolado, em Docker Compose, com volume persistente.
- Variaveis de conexao sem senhas versionadas.
- Teste SQL real via **Prisma 6.19.3**, aproveitando `prisma/postgresql/schema.prisma` ja existente no GitHub.
- Nenhuma alteracao de tabelas, migracoes, endpoints, `prisma/schema.prisma` (SQLite) ou `.env` atual.

**Importante:** esta etapa prepara e testa o banco. O `ddl.sql`, o `seed_dml.sql` e a adequacao das 13 tabelas ficam para PI4-242 e PI4-243.

## Pre-requisitos

- Windows com Docker Desktop iniciado e Docker Compose v2; se ja possui PostgreSQL instalado, pode usa-lo em vez do contêiner, ajustando host/porta e credenciais.
- Node.js >=22.12 e `npm ci` (o projeto fixa Prisma 6.19.3).
- Executar os comandos da **raiz** de `folcstore-backend`.

## Instalar arquivos

Copie do ZIP para a raiz do repositorio, preservando os caminhos:

```text
compose.postgres.yaml
postgres.example.env
scripts/pi4-241-conexao.sql
scripts/pi4-241-verificar-postgres.mjs
docs/PI4-241.md
```

**Nao sobrescreva** `prisma/schema.prisma`, `prisma/postgresql/schema.prisma`, `.env` ou migrations existentes.

## Teste — PowerShell

```powershell
# opcional: use uma branch propria
# git checkout -b feature/pi4-241-postgresql
npm ci
Copy-Item postgres.example.env .env.postgres
notepad .env.postgres
```

No `.env.postgres`, substitua `SUBSTITUA_POR_SENHA_FORTE` por uma senha local forte. Esse arquivo nao deve ser enviado ao Git: o `.gitignore` existente ja ignora `.env.*`.

```powershell
# Iniciar o banco na porta 5433
# A porta 5433 evita conflito com PostgreSQL instalado na 5432.
docker compose --env-file .env.postgres -f compose.postgres.yaml up -d postgres

# Verificar status: deve aparecer healthy apos a inicializacao
docker compose --env-file .env.postgres -f compose.postgres.yaml ps

# Teste de consulta no proprio PostgreSQL (valores padrao do exemplo)
docker compose --env-file .env.postgres -f compose.postgres.yaml exec postgres psql -U folcstore -d folcstore -c "SELECT current_database(), current_user;"

# Testar SQL via Prisma, SEM criar nenhuma tabela
node scripts/pi4-241-verificar-postgres.mjs
```

**Saida esperada ao final do script:**

```text
SUCESSO PI4-241: PostgreSQL acessivel pelo Prisma. Nenhuma tabela foi criada.
```

Se personalizar `POSTGRES_USER` ou `POSTGRES_DB`, ajuste o comando `psql` de acordo. O script Node detecta esses valores automaticamente do `.env.postgres`.

Para verificar que esta historia nao criou tabelas (banco novo):

```powershell
docker compose --env-file .env.postgres -f compose.postgres.yaml exec postgres psql -U folcstore -d folcstore -c "\dt"
```

Um banco novo normalmente responde `Did not find any relations.`

## Cuidados

- **Nao rode** `npm run db:migrate`: `scripts/migrate.ts` atual exige SQLite (`file:`).
- **Nao rode** `prisma migrate dev`, `migrate deploy`, `db push` ou `npm run db:seed` nesta historia: o schema PostgreSQL antigo ainda nao corresponde ao modelo da PI4-240.
- **Nao altere** o `.env` de uso diario do backend: esta verificacao injeta temporariamente as URLs PostgreSQL apenas no processo Prisma.
- **Nao use** `docker compose down -v`, que apaga os dados armazenados no volume.
- Para parar sem apagar o volume: `docker compose --env-file .env.postgres -f compose.postgres.yaml stop`.
- Se trocar usuario/senha/nome do banco **apos** a primeira inicializacao, os dados do volume existente nao serao reconfigurados automaticamente. Alinhe credenciais com o ambiente inicializado.
- Nao use dados pessoais reais nem publique senhas ou URLs privadas.
