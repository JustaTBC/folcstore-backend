# PI4-244 — Documentar e apresentar o modelo físico do FolcStore

> **Entrega de Banco de Dados da AV2 | prazo: 07/12/2026**  
> Este material complementa os SQLs existentes de PI4-242 (`ddl.sql`) e PI4-243 (`seed_dml.sql`). **Não substitui os arquivos anteriores nem altera o backend.**

## 1. Problema e solução

O FolcStore organiza a comercialização de peças artesanais, conectando compradores e artesãos. Sem um banco relacional estruturado, o sistema pode apresentar inconsistências de estoque, preços, destinatários, pedidos e avaliações. O modelo físico em PostgreSQL organiza esses dados em **13 tabelas**, com relacionamentos e restrições que evitam parte desses problemas diretamente no banco.

## 2. Modelo físico e decisões técnicas

Os modelos conceitual e lógico da equipe foram a referência da implementação. A estrutura mantém as especializações `usuarios` → `compradores`, `artesaos`, `administradores`, e separa produtos, carrinhos, pedidos, endereços, imagens, postagens e avaliações. Relacionamentos N:M com dados próprios são materializados por `itens_carrinho` e `itens_pedido`, ambos com **chaves primárias compostas**.

| Decisão | Justificativa e exemplo |
|---|---|
| `INTEGER GENERATED BY DEFAULT AS IDENTITY` | Identificadores inteiros conforme o modelo lógico; FKs têm o mesmo tipo. |
| `NUMERIC(12,2)` | Precisão decimal para preços e totais, como `produtos.preco` e `pedidos.valor_total`. |
| `TIMESTAMPTZ`, `DATE`, `BOOLEAN`, `VARCHAR` e `TEXT` | Tipos adequados a datas, estado ativo, identificadores textuais e descrições. |
| PK/FK nomeadas | Garantem identificação e integridade referencial; `ON DELETE RESTRICT` protege referências históricas. |
| `ON DELETE CASCADE` seletivo | Imagens de um produto e itens de um carrinho são dependentes e podem ser excluídos com a entidade pai. |
| `UNIQUE` e `NOT NULL` | Ex.: e-mail de usuário único; campos essenciais obrigatórios. |
| `CHECK` | Ex.: `preco > 0`, `quantidade_estoque >= 0`, `nota BETWEEN 1 AND 5`, estados permitidos, `subtotal = quantidade * preco_unitario`. |
| Categorias textuais | `produtos.categoria` respeita o modelo lógico da disciplina. |
| Endereços de entrega | `pedidos.id_endereco` permite entrega em endereço diverso da residência do comprador. |

**Status de produtos:** `RASCUNHO`, `ATIVO`, `PAUSADO`, `INATIVO`.  
**Status de pedidos:** `PENDENTE`, `CONFIRMADO`, `EM_PREPARACAO`, `ENVIADO`, `ENTREGUE`, `CANCELADO`.

**Limites conhecidos:** o DDL não impõe sozinho que `pedidos.valor_total` corresponda à soma de seus itens, nem que uma avaliação seja de compra entregue. Essas consistências foram verificadas no **seed demonstrativo** por consultas de validação e precisarão ser garantidas pela camada de serviço ou por regras adicionais em evoluções futuras. A aplicação Prisma/Express atual ainda usa um schema legado com UUIDs e preços em centavos; **não execute `prisma db push` ou migrations legadas sobre o banco acadêmico**.

### Demonstrar duas falhas com a mensagem nativa de `ERROR`

O PDF solicita que apareça a **mensagem do banco bloqueando os dados inválidos**. Os scripts anteriores de teste capturam o erro e imprimem `NOTICE: OK`; para o vídeo, use os dois exemplos abaixo que deixam o PostgreSQL exibir o erro original.

```powershell
# 6. Falha proposital: preco negativo — deve mostrar ERROR com ck_produtos_preco
docker compose --env-file .env.postgres -f compose.postgres.yaml exec -T postgres psql -U folcstore -d folcstore_av2_demo -v ON_ERROR_STOP=1 -f /tmp/pi4244_erro_check_visivel.sql

# 7. Falha proposital: artesao inexistente — deve mostrar ERROR com fk_postagens_artesaos
docker compose --env-file .env.postgres -f compose.postgres.yaml exec -T postgres psql -U folcstore -d folcstore_av2_demo -v ON_ERROR_STOP=1 -f /tmp/pi4244_erro_fk_visivel.sql
```

**Esses dois comandos devem falhar (código de saída diferente de zero). Isso é o resultado esperado.** As inserções inválidas são recusadas, portanto nenhum registro inválido é gravado. Depois de mostrar os `ERROR`, explique por que cada restrição é importante. Para testes automatizados que terminam sem erro, use `testes_povoamento.sql` da PI4-243.

Não execute `docker compose down -v` e **não remova** o banco `folcstore`. O banco isolado pode permanecer para documentar a execução; o script não o substitui ao ser chamado novamente.
